# 電力-checklist — TurboPi 供電改造與續航評估

電池規格（使用者回報）：**Hiwonder、18650、單顆 3.7V / 2200 mAh、鋰電、共 2 顆**

---

## 0. 已確定的事實（本輪實測）

- 機器先前**由 USB-C 行動電源供電**，該行動電源耗盡 → 整台**直接斷電關機**（`HW-6720577E` AP 消失、SSH timeout）
- 這代表：**它之前是「硬吃 5V 外部供電」在跑**，而不是吃車上那兩顆 18650
- 我讀過的 `/ros_robot_controller/battery`（`UInt16`，約 9 Hz）：
  `4475 4476 4481 4491 4506 4507 4509 4511 4517 4518 4520 4523 4524`

### 🔴 重要判讀：那個欄位**不是**電池電壓

用規格反推就能排除：

| 假設 | 若成立則 4524 代表 | 判定 |
| :-- | :-- | :-- |
| 2S 電池總壓(mV) | 4.52 V（每 cell 2.26 V） | 深度過放，BMS 早就切斷，機器根本跑不起來 ⇒ **不合理** |
| 單顆 cell 電壓(mV) | 4.52 V | **超過鋰電 4.20 V 上限，物理上不可能** |
| **5V 電源軌** | 4.52 V（行動電源快沒電時的 5V 墬陷） | ✅ 最合理，而且**與「行動電源耗盡→整台斷電」完全吻合** |

⇒ **結論：`/ros_robot_controller/battery` 量的是板上電源軌（約 5V），不是 18650 的電量。**
換言之：**我們至今無法從軟體得知那兩顆電池的剩餘電量。**（`/sys/class/power_supply/` 也是空的，OS 層看不到任何電池。）

> 驗法（充飽後一次就能定案）：改用電池供電、拔掉所有外部電源，再看這個欄位。
> - 讀到 **6000–8400** ⇒ 它其實量的是 2S 電池總壓(mV)，那我上面的判讀要改
> - 仍讀 **4300–5200** ⇒ 確定是 5V 軌，電量必須靠三用電表或加裝庫侖計

---

## 1. 先做：充電前的安全檢查（很關鍵，因為這組電池剛剛被放到機器自己關機）

鋰電被放到電腦關機，代表可能已經接近或低於截止電壓。**先量再充**：

| 單顆實測電壓 | 處置 |
| :-- | :-- |
| ≥ 3.0 V | 正常充電 |
| 2.0 – 2.9 V | **低電流**充（≤0.2C ≈ ≤0.45 A），全程在旁看守、摸溫度；充到 3.0V 後才可轉正常電流 |
| < 2.0 V | **不要在無人看管下充電**（內部可能已短路，有起火風險）→ 回收處理 |
| 外殼鼓包 / 充電時發燙 >45°C / 有異味 | 立刻停用、退役 |

- 建議**用獨立 18650 充電器逐顆充**（而不是透過車上充電電路），這樣可以：
  1. 逐顆看每顆的實際容量（若充電器有容量計功能）
  2. 找出「是否有一顆明顯衰敗」— 兩顆串聯時** weakest cell 決定整組**
- 充電電流：2200 mAh ⇒ 1C = 2.2 A；一般用 **1 A**，約 2.5–3 小時充滿
- 充滿判準：**4.20 V/顆**（2S 總壓 8.40 V）

## 2. 一定要搞清楚的一件事：2S 還是 2P？

「18650 ×2」有兩種接法，**能量一樣但電路行為完全不同**：

| 接法 | 總壓 | 容量 | 能量 | 板上的 DC-DC |
| :-- | :-- | :-- | :-- | :-- |
| **2S1P**（Hiwonder 常見） | 7.4 V 標稱 / 8.4 V 滿 | 2200 mAh | 16.3 Wh | buck 降壓到 5V，餘裕較好 |
| **2P1S** | 3.7 V 標稱 / 4.2 V 滿 | 4400 mAh | 16.3 Wh | 需 boost，電流翻倍，**大電流時 5V 更容易垮** |

**用三用電表量接頭總壓就知道**：≈7.4–8.4 V ⇒ 2S；≈3.7–4.2 V ⇒ 2P。
這條資訊決定了「能不能同時跑 Pi 5 + 四顆馬達」的答案，務必量並記錄。

## 3. 續航估算（以 16.3 Wh、DC-DC 效率 ~85% ⇒ 可用 ≈13.9 Wh）

| 工況 | 粗估功率 | 續航 |
| :-- | :-- | :-- |
| 開機靜置、SSH 觀察 | 6–8 W | ~1.7–2.3 h |
| 跑 ROS 堆疊 + 相機 + AP/STA 雙無線電 | 9–12 W | **~1.2–1.5 h** |
| 一邊跑視覺一邊低速走 | 15–20 W | **~40–55 min** |
| 走走停停 + 轉向/爬坡（馬達突波） | 25–40 W | **~20–35 min** |

⚠️ 舊 18650（2200 mAh 通常是較老的型號，若實測剩 <1400 mAh ≈ 65% SOH）→ 上面數字全部打 6 折。

## 4. Pi 5 的供電門檻（這是最可能出事的點）

- Pi 5 官方建議 **5V / 5A（25W）**；USB-C 支援 PD。外設：相機 + USB WiFi + Docker/ROS 全開
- **馬達啟動瞬間的突波**會把 5V 軌拉垮 → 不是「慢下來」而是**直接重啟或 SD 卡寫入損毀**
- 偵測方法（唯一可靠的軟體證據）：
  ```bash
  vcgencmd get_throttled
  # 0x0                     = 供電一直正常
  # bit0 0x1                = 目前偵測到 undervoltage  ← 看到就立刻停
  # bit4 0x10000            = 曾經發生過 undervoltage
  # bit2/bit3 0x4/0x8       = 降頻/溫度上限（不是供電問題）
  ```
- **目前讀過的 `get_throttled=0x0`**，但那是「行動電源供電 + 沒驅動馬達」的狀態，**不能外推到電池供電 + 馬達負載**

## 5. 換成電池跑的標準流程（逐級加載，任何一級出現 throttled≠0 就停）

1. **先做備份**（根分割區 92%、`mentorpi` 映像沒有備份 → 一次斷電可能就得整卡重拷）
2. 正常 `shutdown` → 拔所有外部電源 → 開車上開關 → 開機
3. 桌機先起儀表板：`python3 work/power-check/power_watch.py 900`
4. **第 1 級**：開機靜置 5 分鐘 → 看 `throttled`、`battery` 值域（順便定案那個欄位到底是什麼）
5. **第 2 級**：跑相機 + 視覺節點 5 分鐘 → 看 `core_volts` / `temp`
6. **第 3 級**：**短時間低速**走動（前後各 2 秒、轉向 2 秒）→ 緊盯 `bit0`；這是最關鍵的一級
7. 通過才可開始實戰；不通過的解法依序：換更高電流電池/換 2S、把馬達供電與 Pi 供電**分離**（獨立 BEC 或第二個 5V buck）、或 Pi 改用 PD 電源模組

## 6. 待補（可選，讓電量变成可觀測量）

- 加裝**庫侖計**（INA219/INA226 + I2C，`0x48` 已被 ADS7830 佔用 → 用 `0x40–0x47` 空位）→ 就能做「電壓 + 電流 + 剩餘容量」的即時儀表板，也能做低電壓自動安全停機
- 或在主控板的空 ADC 通道（ADS7830 有 8 通道）接電池總壓分壓 → 用現成硬體做出真實電壓讀值
